# P0-5 数据采集、增强与划分顺序溯源

## 结论

**ORIGINAL ACQUISITION PROVENANCE = PARTIAL。** 本轮首次将当前 8940 个数据文件完整连接到指定上游固定树，并确认相关重复/旋转文件在上游发布时已存在；但原始相机采集 ID、离线增强生成记录和划分形成顺序仍缺失。不能据此宣称“先增强后划分”已经得到直接证明。

## 1. 上游发布历史：事实

官方来源：[DHW-Master/NEU_Seg](https://github.com/DHW-Master/NEU_Seg) 及 [两次提交的比较](https://github.com/DHW-Master/NEU_Seg/compare/c2f2f3a6e561a8cd8bff6e7c15bf1041ade78150...da8cebedb292beca4d101db8c442d5706fac3bfe)。

- 根提交 `c2f2f3a6e561a8cd8bff6e7c15bf1041ade78150` 时间为 2020-12-30T13:12:59Z，无父提交。
- 指定提交 `da8cebedb292beca4d101db8c442d5706fac3bfe` 时间为 2020-12-30T13:48:11Z；与根提交相比只新增一行 `README.md`。
- 因而 4470 张图像、4470 张标注及 `training/test` 目录在根提交中已存在。
- 固定树共有 8941 个普通文件：4470 JPG、4470 PNG、1 个一行 README；没有 `.py/.sh/.ipynb` 等生成脚本，也没有 LabelMe JSON、类别顺序表或划分元数据。
- 当前本地 8940 个数据文件与该固定树全部逐字节一致，见 `upstream_identity_summary.json`。

这些事实把“观察到同源/重复关系的时间边界”推进到上游发布版本，但不恢复发布前的制作顺序。

## 2. 本地制备与训练记录：事实

- 既有本地 README 只有数据集标题；v10.6 已记录未找到原始下载记录、LabelMe 或类别元数据。本轮固定上游核验补上了“当前文件对应哪个公开版本”，没有补上最初下载操作记录。
- 实际训练链只有运行时 `DataGenerator + Transforms_PIL` 在线增强，详见 `actual_training_input_identity.md`。该过程不写回原始图像或 GT。
- `new (copy)/data3.py:5-39` 的功能是把已有 test 灰度标注转成彩色可视图，并写入另一个 `annotations/tests/` 路径；它不是 train/test 划分生成脚本，也未发现其生成当前训练输入的运行证据。
- 历史训练脚本读取既有 `train_neu.txt/test_neu.txt`；本轮未找到生成这两个清单的脚本、随机划分种子、复制/重命名日志或离线重编码记录。
- `train_neu.txt` 的现有行序只是 DataLoader 前的清单顺序；正式训练另设 `shuffle=True`。清单行序不能证明上游划分算法或时间顺序。

## 3. 五种可能性逐项判定

| 可能性 | 判定 | 证据与缺口 |
|---|---|---|
| A. 同一原图先旋转增强，再分到 train/test | **相容但未直接证明** | `test:000717` 与 `train:004097` 存在精确 r180 图像关系，其他 GT+图像候选也相容；但没有生成日志、原始采集 ID 或时间顺序，不能认定“先增强后划分”。 |
| B. 上游发布数据已包含多个同源版本 | **事实（数字/变换/候选层级分开）** | 所有本地文件与上游固定树同字节，四对同图不同 GT、跨 split r180 图像对及大量 GT D4 关系均存在于该树。采集级“同源”仍需按证据等级表述。 |
| C. 划分前已有重复图像但不同标注 | **重复现象存在于上游；相对划分顺序未确认** | 上游 train/test 目录中确有同图不同 GT；无法从两次提交恢复“先重复再划分”还是其他制作顺序。 |
| D. 当前项目后处理或复制引入重复 | **对本轮已检测关系不支持** | 当前 8940 文件与上游完全同字节，已检测关系并非本轮项目复制新产生；这不等于证明项目历史上从未发生任何其他处理。 |
| E. 仍无法确定采集—增强—划分顺序 | **成立** | 缺原始采集表、生成脚本、划分脚本和时间序列。A/B/C 的相容解释必须同时保留。 |

## 4. 原始 ID 与类别语义

- 文件名 `000001` 等只是当前记录标识，不能自动当作原始相机采集 ID。
- 固定上游没有整数 ID 到缺陷名称的元数据；本轮没有新增上游类别语义认证。统计继续使用 `class_id1/2/3`，不凭外观命名。
- GitHub API 的仓库 license 字段为 null，固定树没有 LICENSE 文件；本轮没有建立 GT 再分发授权。公开审计包只放元数据、方法、统计和哈希，不放原始图像、GT 或上游归档。

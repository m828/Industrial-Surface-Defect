# P0-2 全量精确重复与 D4 变换查重

## 覆盖与方法

- 记录键为 `(split, sample_id)`，共 train 3630、test 840、合计 4470 条；没有只用 sample_id 合并跨 split 同名记录。
- 全部图像解码为 RGB、全部 GT 解码为 8bit 灰度；所有图像/GT 均为 200×200，GT 标签均在 `{0,1,2,3}`，图像与 GT 尺寸一致。
- 分别计算原文件 SHA-256、解码像素 SHA-256 和八种 D4 变换后的像素 SHA-256。D4 为 0°/90°/180°/270°及旋转后的水平镜像，不插值、不重标注。
- 所有无序记录对及所有精确 D4 组均展开；transform 字段保存 `transform(A) == B` 的实际方向。四个已知同图对和六组旋转 GT 正例全部通过。

### 新增跨 split 图像精确关系

`test:000717` 旋转 180° 后与 `train:004097` **逐像素完全相同**。两条原始 JPEG 文件字节不同，但解码后存在精确 D4 等价关系。

对应 GT 在相同 180° 对齐下并不相同：

- GT 不同像素：4682；
- 像素一致率：0.88295；
- 非零前景 IoU：0.49709989258861437。

这是 `TRANSFORM_EQUIVALENCE_VERIFIED` 的图像证据，不是“相同 GT 版本”的证据。两条记录在上游固定 commit 中也逐字节存在，因此该关系不是本项目近期复制数据时新引入的。

## 3. 解释边界

1. **数字图像身份**只由原始文件/解码像素关系建立。
2. **图像变换等价**只由图像 D4 精确关系建立；GT-only 关系不加入该层。
3. 大量 GT D4 重复说明标注形状可跨不同图像复现。GT 相同或旋转后相同不能自动推出原图同源，更不能单独推出相同相机采集。
4. 近重复候选受既定检索、方向选择与阈值规则限制，不证明未检出的来源关系不存在；第一版 LSH 近重复汇总存在索引顺序缺陷，见 `original_lsh_run_defect_notice.json`。`exhaustive_hamming/` 是第一遍部分精核结果；权威合并结果以 `cap_resolution/` 为准，并须通过独立复核。
5. 本文件的精确数值来自 `exact_duplicate_summary.json`、`d4_duplicate_summary.json` 和 `d4_transform_duplicate_pairs.csv`；原始数据未被修改。

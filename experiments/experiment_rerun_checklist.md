## 第一优先级：必须重跑（共 7 项）

### R1. A2MS-DefectNet-B NEU-Seg 重新训练

| 项目 | 说明 |
|---|---|
| 严重性 | 🔴 阻塞论文。当前 mIoU=71.31 远低于历史 91.3 |
| 问题描述 | 新训练的模型 mIoU 仅为 71.31，crazing IoU=0.5391、patches IoU=0.5324。可能原因：训练配置错误、detailloss 权重不当、模型初始化问题 |
| 建议行动 | 1. 检查 `train_neu_resnet_detailloss.py` 的损失权重和 detailloss 配置<br>2. 对比历史训练日志和 config 参数<br>3. 用 `dsmonet_resnet_detailloss.yml` 重新训练 |
| 预计耗时 | ~12-24h (A100, 60000 iters) |

### R2. Leather 数据集统一评估（所有模型）

| 项目 | 说明 |
|---|---|
| 严重性 | 🔴 阻塞论文。所有 Leather 模型历史值 vs 新训练值不一致 |
| 问题描述 | 历史声称值 (88.1-91.0) vs 旧评估 (86.07-88.06) vs 新训练 (82.78-85.60)。三者无法对齐。可能原因：评估集不同（验证 234 vs 测试 467 vs 历史 468）、权重版本不同、预处理不同 |
| 受影响模型 | Base-S, Base-B, A2MS-S, A2MS-B, DDRNet, PIDNet-S, STDC1-Seg |
| 建议行动 | 1. 统一使用 `new (copy)/dataset/pige/test.txt` (467 张) 作为评估集<br>2. 使用统一评估脚本 `tools/evaluate_class_iou.py`<br>3. 固定预处理 pipeline (TestRescale + ToTensor, 768×768)<br>4. 选择每个模型的最佳权重<br>5. 记录评估命令和结果 |
| 预计耗时 | ~2h (A100, 批量评估 7 个模型) |

### R3. 所有模型 Per-Class IoU 重跑

| 项目 | 说明 |
|---|---|
| 严重性 | 🟡 中度。现有 per-class IoU 数据来源混杂且不一致 |
| 问题描述 | 当前 class_iou_results.csv 混合了 `evaluate_class_iou.py` 评估（测试集 468 张）和训练日志提取（验证集 234 张），mIoU 不可对齐 |
| 受影响模型 | 所有 11 个新训练模型 + STDC1-Seg、STDC2-Seg |
| 建议行动 | 使用统一评估脚本在同一测试集上重新评估所有模型 |
| 预计耗时 | ~1h (A100) |

### R4. FPS 在 RTX 3090 上重新测量

| 项目 | 说明 |
|---|---|
| 严重性 | 🟡 中度。论文声称 FPS 来自 RTX 3090，但当前数据来自 A100 |
| 问题描述 | 论文实验设置标注 RTX 3090，但所有复杂度统计使用 A100 测量。两平台 FPS 可能不一致（尤其在 batch>1 时） |
| 受影响模型 | 全部 10+ 模型 |
| 建议行动 | 1. 在 RTX 3090 上重新运行 `experiments/scripts/complexity_stats.py`<br>2. 或在论文中明确标注 A100 平台并统一使用 A100 FPS<br>3. 不可混用两个平台的 FPS |
| 预计耗时 | ~2h (RTX 3090) |

### R5. 小目标/细长缺陷分组评价重跑

| 项目 | 说明 |
|---|---|
| 严重性 | 🟡 中度。现有分组评价存在方法论问题且仅覆盖 3 个模型 |
| 问题描述 | 1. "无缺陷" 组 mIoU ≈ 0.125 异常（应接近 1.0）<br>2. 仅 3 个模型有数据<br>3. A2MS-B 在小目标上 (0.4084) 差于 Base-B (0.5141)，与论文结论矛盾<br>4. 分组基于连通域近似而非标签 |
| 建议行动 | 1. 修复无缺陷样本的评估逻辑<br>2. 扩展到所有 7+ 模型<br>3. 输出样本 ID 便于追溯<br>4. 检查 A2MS-B 小目标评估是否正确 |
| 预计耗时 | ~3h (A100) |

### R6. 可视化结果重新生成

| 项目 | 说明 |
|---|---|
| 严重性 | 🟡 中度。当前可视化存在选择偏差和样本量不足问题 |
| 问题描述 | 1. 部分场景仅 1 个样本<br>2. 无失败案例<br>3. CJK 字体缺失 |
| 建议行动 | 1. 每个场景至少 3-5 个样本<br>2. 补充 A2MS 劣于 Base 的案例<br>3. 补充两者均失败的案例<br>4. 修复 CJK 字体或使用英文标题<br>5. 记录所有样本 ID 和预测路径 |
| 预计耗时 | ~2h |

### R7. 不可追溯对比方法基线重建

|---|---|
| 严重性 | 🟡 中度。论文主实验表中多个对比方法无权重/代码 |

| 预计耗时 | 每模型 ~12-24h，建议并行 |

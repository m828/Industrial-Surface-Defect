## 二、平台差异分析

### A100 vs RTX 3090 FPS 差异

| 模型 | 历史 RTX 3090 FPS@200 | 当前 A100 FPS@200 | 差异 |
|---|---:|---:|---|
| Base-S | 178.5 | 149.7 | -28.8 (-16%) |
| Base-B | 115.6 | 99.9 | -15.7 (-14%) |
| A2MS-S | 196.5 | 170.8 | -25.7 (-13%) |
| A2MS-B | 127.9 | 100.3 | -27.6 (-22%) |

**差异分析**：
- A100 FPS 反低于 RTX 3090，这不符合常理（A100 应更快）
- 可能原因：
  1. 历史 FPS 测量方式不同（无 synchronize？batch>1 取平均？）
  2. 历史 FPS 可能包含 TensorRT/FP16 优化
  3. 历史 FPS 的预处理/后处理计时方式不同
  4. PyTorch 版本差异（1.10 vs 当前版本）
  5. 历史 FPS 数值来源可能不可靠

**结论**：两平台 FPS 不可直接比较，必须统一。

## 三、方案对比

### 方案 A：坚守 RTX 3090（与论文一致）

**优点**：
- 与论文实验设置声明一致（fixed_existing_results.md 标注 RTX 3090）
- 不需要修改论文正文

**缺点**：
- 当前 A100 新训练 + RTX 3090 FPS 来自不同硬件，存在方法论矛盾
- RTX 3090 当前不可用 → 需要寻找 RTX 3090 机器
- 历史 FPS 测量方法不透明，可能无法复现

**行动**：
1. 确认是否有 RTX 3090 可用
2. 在 RTX 3090 上严格按照 `complexity_stats.py` 方法重新测量所有模型
3. 记录具体测量参数和代码

### 方案 B：切换为 A100（统一平台）

**优点**：
- 所有新训练和评估在同一平台，方法论一致
- A100 可用且稳定
- FPS 相对排名（模型间比较）在不同平台通常保持一致

**缺点**：
- 需要修改 fixed_existing_results.md 和论文正文的硬件标注
- 论文中的 Sub-region UNet, SFNet, FDSNet 等方法的 FPS 来自 RTX 3090 → 不可与新 FPS 直接比较
- 审稿人可能质疑：为什么中途更换 GPU

**行动**：
1. 修改论文实验设置标注为 "NVIDIA A100-PCIE-40GB"
2. 将 A100 FPS 写入主实验表
3. 历史对比方法 FPS 标注为 "引用原论文" 或 "在不同硬件上测量"

### 方案 C：两平台都列（折中）

**优点**：
- 保留历史数据完整性
- 标注清晰后不构成学术不端

**缺点**：
- 读者可能困惑为什么有两个平台的 FPS
- 增加论文篇幅

**不建议**：容易引起误解。

---

## 四、推荐方案

```
推荐方案 B：统一使用 A100 作为 FPS 平台
```

**理由**：
1. A100 是当前可用的唯一 GPU，所有新训练在此完成
2. 历史 RTX 3090 FPS 无法在当前服务器复现和验证
3. FPS 的相对排名（A2MS-S > Base-S, 轻量模型 > 重量模型）在 A100 和 RTX 3090 上一致
4. 学术透明：明确标注 A100 平台比模糊引用 RTX 3090 更可靠

**需要的改动**：
1. `fixed_existing_results.md` → 更新硬件标注为 A100
2. 论文正文 → 实验设置节更新 GPU 标注
3. 论文所有 FPS 数值 → 替换为 A100 测量值
4. 对比方法表中 FPS → 标注 "† 在不同硬件上测量" 或仅保留可复现方法

**不需要改动的**：
- mIoU / Params / FLOPs → 与 GPU 无关，可直接使用
